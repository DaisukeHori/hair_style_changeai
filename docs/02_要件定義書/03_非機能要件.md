## 3.2 可用性要件

| 項目 | 要件 |
|------|------|
| サービス時間 | 24時間365日 |

| 年間最大停止時間 | 43.8時間以内 |

### 3.2.2 障害復旧

```
障害復旧目標
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

【RPO（Recovery Point Objective）: 目標復旧時点】
└── 1時間以内
    └── 最大1時間分のデータ損失を許容

【RTO（Recovery Time Objective）: 目標復旧時間】
└── 4時間以内
    └── 障害発生から4時間以内にサービス再開

【障害レベル別復旧時間】
├── レベル1（軽微）: 30分以内
│   └── 一部機能の遅延・軽微な不具合
│
├── レベル2（中程度）: 2時間以内
│   └── 主要機能の一部が使用不可
│
└── レベル3（重大）: 4時間以内
    └── システム全体が使用不可
```

## 3.3 セキュリティ要件

### 3.3.1 認証・認可

| 要件 | 実装方式 |
|------|---------|
| 認証方式 | メール/パスワード + JWT |
| パスワードポリシー | 8文字以上、英数混合 |

| 多要素認証 | 将来オプション |
| アカウントロック | 5回失敗で10分ロック |

### 3.3.2 アクセス制御

```
アクセス制御モデル
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

【RBAC（Role-Based Access Control）】

ロール階層:
├── owner（オーナー）
│   └── 全権限
│
├── manager（マネージャー）
│   ├── スタッフ管理
│   ├── レポート閲覧
│   └── 設定変更
│
├── stylist（スタイリスト）
│   ├── カルテ編集
│   ├── 施術記録
│   └── 予約管理
│
└── assistant（アシスタント）
    ├── カルテ閲覧（制限付き）
    └── 施術補助記録

【マルチテナント分離】
└── salon_id による Row Level Security (RLS)
    └── 他店舗のデータにはアクセス不可
```
