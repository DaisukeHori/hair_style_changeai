## 5.2 エンティティ定義

### 5.2.1 salons（美容室）

| カラム名 | データ型 | NULL | 制約 | 説明 |
|---------|---------|:----:|------|------|
| id | UUID | NO | PK | 主キー |
| name | VARCHAR(100) | NO | | 美容室名 |
| address | VARCHAR(255) | YES | | 住所 |
| phone | VARCHAR(20) | YES | | 電話番号 |
| email | VARCHAR(255) | YES | UNIQUE | メールアドレス |
| business_hours | JSONB | YES | | 営業時間 |
| logo_url | VARCHAR(500) | YES | | ロゴ画像URL |
| settings | JSONB | YES | | 店舗設定 |
| created_at | TIMESTAMP | NO | DEFAULT NOW() | 作成日時 |
| updated_at | TIMESTAMP | NO | | 更新日時 |

**business_hours JSONB構造**:
```json
{
  "monday": {"open": "09:00", "close": "19:00"},
  "tuesday": {"open": "09:00", "close": "19:00"},
  "wednesday": null,
  "thursday": {"open": "09:00", "close": "19:00"},
  "friday": {"open": "09:00", "close": "19:00"},
  "saturday": {"open": "09:00", "close": "18:00"},
  "sunday": {"open": "10:00", "close": "17:00"},
  "holidays": "closed"

```

## 5.4 データ移行要件

### 5.4.1 移行対象データ

```
データ移行計画
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

【既存データ移行（必要な場合）】
├── 顧客基本情報
│   ├── CSV/Excelからインポート
│   └── 必須項目のマッピング
│
├── 施術履歴
│   ├── 過去データの構造化
│   └── 詳細情報の変換
│
└── 写真データ
    ├── 既存画像のアップロード
    └── メタデータ付与
```

### 5.4.2 データ品質要件

| 要件 | 内容 |
|------|------|
| 重複チェック | 電話番号・メールで重複顧客検出 |
| 必須項目 | 氏名は必須、連絡先は電話orメール必須 |
| フォーマット | 電話番号・メールの形式チェック |
| 文字コード | UTF-8統一 |

## 5.5 データ保持・削除ポリシー

### 5.5.1 保持期間

| データ種別 | 保持期間 | 理由 |
|-----------|---------|------|
| 顧客データ | 最終来店から3年 | 再来店可能性 |
| 施術記録 | 10年間 | 施術履歴の参照 |
| 写真データ | 5年間 | 容量・コスト考慮 |
| シミュレーション | 2年間 | 参考用 |
| ログデータ | 90日間 | 調査用 |

### 5.5.2 削除処理

```
データ削除フロー
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

【顧客からの削除要請】
├── 本人確認
├── 削除対象の特定
├── 関連データの削除
│   ├── 施術記録
│   ├── 写真
│   └── シミュレーション
├── 論理削除 or 物理削除
└── 削除完了通知

【自動削除（定期バッチ）】
├── 保持期間超過データの抽出
├── 削除対象のバックアップ
├── 削除実行
└── 削除ログ記録
```
